# Nano | نانو — Flet Business Suite

مشروع Nano هو تطبيق محاسبة ومخزون ومبيعات يعمل محليًا باستخدام Flet/Python وSQLite. جميع العمليات الأساسية محلية على الجهاز، بينما الشبكة مخصصة للتفعيل فقط عبر نفس بروتوكول هوى الشام.

## المرحلة الحالية: Phase 7.2

- SQLite محلي مع WAL وForeign Keys وTransactions.
- Schema Version 5 مع ترحيل غير هدّام من المراحل السابقة.
- العملاء والموردون والمواد والخدمات والوحدات والتحويلات.
- فواتير بيع وشراء متعددة البنود مع تعديل وحذف وإعادة بناء للمخزون وCOGS.
- تكلفة معيارية للخدمات تُلتقط داخل بند فاتورة البيع تاريخيًا ولا تتغير عند تعديل تكلفة الخدمة لاحقًا.
- سندات قبض وصرف ودفعات لاحقة وتوزيع تلقائي/يدوي.
- أرصدة دائنة ودفعات مقدمة ومصروفات وتصنيفات.
- كشوف حساب ودفتر أستاذ محلي.
- مركز تقارير: الربحية، المخزون، الذمم، الفواتير المفتوحة، والصندوق.
- مستخدمون محليون بأدوار `admin/accountant/sales/viewer`.
- كلمات مرور PBKDF2-HMAC-SHA256 + Salt وقفل مؤقت للمحاولات الفاشلة.
- سجل تدقيق مرتبط تلقائيًا بالمستخدم الحالي.
- Backup موثق ببصمة SHA-256 وفحص SQLite، مع Safety Backup قبل الاسترجاع.
- مشاركة Backup على Android عبر Share Sheet واستيراد `.nanobackup` (مع بقاء دعم استيراد `.qeidbackup` القديمة) من منتقي الملفات عبر إضافة Flutter محلية.
- طباعة الفواتير وكشوف الحساب، ومشاركة PDF، عبر جسر Flutter أصلي محلي.
- قوالب HTML عربية RTL للفواتير وكشوف الحساب، تعمل من SQLite دون Backend.
- الترخيص غير مدرج في النسخ الاحتياطية ويظل مرتبطًا بالجهاز.
- التفعيل يستخدم نفس سيرفر وبروتوكول هوى الشام (`licenseCode` + `fingerprint`).
- بعد نجاح التفعيل يتم فحص الترخيص محليًا ولا تحتاج المحاسبة إلى الإنترنت.
- التفعيل بوابة تشغيل فعلية قبل تسجيل الدخول المحلي.
- قاعدة البيانات على Android تستخدم `FLET_APP_STORAGE_DATA` وليس مجلد Source المعبأ.
- ترحيل تلقائي آمن لقواعد المراحل السابقة إلى مجلد البيانات الدائم.
- إعدادات Android تمنح `INTERNET` للتفعيل فقط وتعطل Android Auto Backup (`allowBackup=false`).
- تنقل الهاتف أصبح مختصرًا: الرئيسية والفواتير والمالية والتقارير، مع تجميع الشاشات الثانوية داخل «المزيد» بحسب صلاحيات المستخدم.
- GitHub Actions جاهز لبناء APK Release ويتحقق من تسجيل إضافة `flet_native_files` داخل مشروع Flutter المولّد قبل قبول البناء.

## التشغيل

```bash
python -m pip install -e extensions/flet_native_files
python -m pip install -e .
flet run src/main.py
```

تسلسل أول تشغيل:

1. التحقق من الترخيص المحلي.
2. إذا لم يكن مفعلًا: شاشة التفعيل عبر سيرفر هوى الشام.
3. بعد نجاح التفعيل: إنشاء المدير الأول.
4. بعد ذلك يصبح تسجيل الدخول والعمل المحاسبي محليين بالكامل.

## سياسة الشبكة

طلب التفعيل يرسل فقط:

```json
{
  "licenseCode": "...",
  "fingerprint": "..."
}
```

ولا يرسل أي فواتير أو عملاء أو موردين أو مواد أو مخزون أو تقارير أو مستخدمين.

## حدود المرحلة الحالية

- خادم هوى الشام الحالي لا يعيد Signed License من الخادم؛ لذلك التحقق المحلي مرتبط بالجهاز ومقاوم للتعديل العرضي، لكنه ليس بديلًا عن توقيع خادم بمفتاح خاص.
- Backup الخارجي غير مشفر حاليًا؛ سلامته محمية بالـmanifest وSHA-256 وفحص SQLite.
- الطباعة ومشاركة PDF ومشاركة/استيراد Backup اجتازت اختبارات التغليف والعقود، لكنها تحتاج اختبارًا فعليًا على جهاز Android بعد بناء APK.
- لم يتم بناء APK فعليًا داخل بيئة الاختبار الحالية لعدم توفر Flet/Flutter Runtime كامل للبناء.


## الهوية البصرية

- الشعار والهوية داخل `branding/`.
- أيقونات التطبيق وملفات Splash داخل `src/assets/` وتُستخدم تلقائيًا من Flet عند البناء.
- ملف بناء APK الجاهز داخل `build_nano_apk.sh` و `build_nano_apk.bat`.

## Nano UX / Release

- الاسم الظاهر والهوية: `Nano | نانو`.
- الحزمة الداخلية: `nano_offline`.
- تبويب **المواد** موضوع مباشرة بعد **الرئيسية** في التنقل المكتبي، وهو ضمن التنقل الأساسي على الهاتف.
- أيقونة التطبيق وSplash مدمجة داخل `src/assets/`.
- شعار الهوية الكامل داخل `branding/`.
- بناء Android: `build_nano_apk.sh` أو `build_nano_apk.bat`، ويُنسخ الناتج إلى `dist/nano-release.apk`.
- ما زال استيراد `.qeidbackup` و`qeid.db` القديم مدعومًا لأغراض التوافق والترحيل.
